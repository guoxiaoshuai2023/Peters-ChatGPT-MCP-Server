# 授权原件读取与交付

本功能让支持文件物化的 ChatGPT 会话自主查找授权 repo/worktree 中的已有文件，再取得未经改写的原件，用原生文件工具验算、解包或看图。服务仅负责来源校验、临时快照和字节交付；不执行项目文件，不建设格式解析器，也不打包整个仓库。

本目录为 `0.4.3-context.1` 隔离开发版本，尚未切换生产。出口默认关闭，必须另行显式配置。既有项目、历史和原件写回权限不会自动扩大。

## 实测适用范围

G0 已验证 ChatGPT Web 的 **GPT-5.6 Sol / Chat / High**，MCP SDK 2.2.0、协议 `2026-07-28`、macOS / Python 3.12。小 ZIP 与约 12.6 MB ZIP 经实际接收、原生 Python 哈希、解包、PNG 显示及隐藏视觉内容核对。Pro 模式、视频审阅、交互浏览和其他格式的原生消费尚未由该证据证明。

选定且仅实现的路线：工具返回 `TextContent + ResourceLink`，宿主经同一认证 MCP 连接发起 `resources/read`，将二进制资源放入会话原生文件环境。宿主可能显示“允许文件实体化”确认。资源地址 `peters-export://…` 只是短期定位符，不授予访问权，也不能映射任意磁盘路径。没有公开下载端点或 Base64 文本拼接备用通道。

初版最大原件为 **12,659,780 字节**，不从更大的服务端缓存预算推断宿主能力。超过上限返回 `client_ingestion_unverified`。资源响应采用 `application/octet-stream`；工具链接的 MIME 是文件名猜测。通道可传普通二进制，但逐格式消费能力必须另行验证。现阶段只给已测试的现代协议签发导出窗口；旧协议的既有工具继续可用。

## 本地配置

使用已有、明确初始化的私有控制目录和已登记暂存根。新出口不会初始化 SQLite、创建写任务、自动创建保护根或启用写回。

1. 按 `ORIGINAL_FILE_SAVE.md` 的基础设施步骤准备私有配置。仅需读取时保持该文件的 `enabled: false`；它仍用于加载已有私有保护和只读任务检查器。
2. 复制 `original-exports.example.json` 到机器自己的私有配置位置，填入已登记的规范绝对 `spool_root`。配置文件须为当前用户拥有的普通单链接文件、权限 `0600`。不要提交真实配置。
3. 在同一文件中显式设置 `enabled: true`。`profile_id` 必须匹配已测试通道；`max_file_bytes` 可降低，不能超过实测上限。`min_free_bytes` 与原件写回的最低空闲量取较大值。
4. 给既有认证源入口增加 `--file-export-config /absolute/path/to/private/original-exports.json`。继续显式提供原有 Access、项目、历史、原件配置。先用 `--check` 验证，再在另行批准的窗口内重启源服务并刷新现有连接的工具定义。

独立出口配置变动和基础设施身份／限制变动会关闭旧来源能力，需协调重启；原件写回的开关本身不自动改变原件读取。关闭出口后，旧记录一旦观察到撤销便不会复活。缺失、损坏或无法确认的私有保护始终关闭访问。

无认证的回环 HTTP 与 stdio 入口保留原来的文本读取行为，但不签发原件出口窗口。可复制的项目配置不包含任何用户授权、本机路径或外部连接。

## 会话调用顺序

1. `list_projects` 获取授权项目及 `original_export.service_instance_id`、当前 `request_window_id`。
2. `list_worktrees` 选择准确的工作目录。新工具必须显式传 `worktree_id`；不会沿路径自动切换到嵌套仓库。
3. `find_files` 按目录、文件名 glob 和扩展名交集查找。扫描包含 `build/dist`，明确报告依赖／缓存跳过和覆盖不足。
4. `export_file` 传项目、工作树、相对路径、当前实例／窗口、新 `request_key`。只有确实已知原 SHA 时才提供 `expected_sha256`。
5. `queued/preparing` 表示进程内已接受，按 `export_id` 查询 `get_file_export_status`。`ready` 才有快照大小、SHA、捕获版本与短期资源链接。
6. 经宿主许可物化后，使用原生工具打开实际文件、计算 SHA 并按任务需要解包、看图。不能把服务返回的 SHA 复述成独立验算。

同一主体在当前 900 秒窗口内用相同 key 和相同意图重试，返回原导出；改变意图为冲突。失败／被淘汰的 key 在窗口结束前也不会重新复制。窗口到期后旧窗口始终拒绝；已接受且仍有效的 `export_id` 可继续读取。若跨窗丢失 ID，不能恢复旧回执，必须显式新请求；需要同内容时使用已知 SHA 约束。

`get_file_export_status` 在服务端不复制、不重新下载、不刷新 TTL 或淘汰顺序。返回 ready 资源时，宿主可能另外显示文件实体化确认，包括重复请求与状态查询；是否物化是客户端的另一项操作。来源普通正文变更后，可以继续取得已捕获的旧快照，其版本与 SHA 不会偷偷变成新内容；链接、权限、根身份或保护失效则终止旧导出。恢复授权后使用新请求。

## 三种不同的回执

- `ready`：服务端已完成匿名快照、独立回读哈希和保护检查。
- `server_stream_finished: true`：服务端至少一次完成该快照的响应发送及实际任务收尾，不等于客户端已保存。
- `client_received: not_observed`：服务不以模型口头声明更新接收状态。最终接收证据来自会话原生文件工具的实际执行结果。

## 边界和资源

出口沿用 repo/worktree 授权、管理员排除和凭据屏蔽，额外保护 Codex 固定状态及 SQLite 旁文件、已知凭据数据库旁文件、真实服务配置／历史目录和私有根。普通应用数据库、项目设置、AGENTS/CI 说明及未知扩展名不会因为写保护规则而一律被禁止。只读普通单链接文件；逐层拒绝符号链接、硬链接和特殊文件。

默认一个准备 worker、两个排队位、两个元数据 worker、每主体一个元数据操作。快照最多全局八个／每主体四个，字节预留最多 256 MiB／128 MiB。所选完整二进制响应一次只发送一个，额外预留 128 MiB 编码预算。实测峰值是观测结果，不是全进程 RSS 硬上限。

快照 ready 最长 600 秒，可因压力提前淘汰未使用件；准备排队 30 秒、准备总时限 600 秒、无进展 30 秒。发送每次交付前检查当前状态；健康验证有效期最多一秒，过期且检查尚未完成时暂停。无法撤回已交给网络或客户端的字节。

断线只结束当前读取，仍有效的快照可从头重取。资源预算在实际所有者、SDK Task 与 ASGI 响应确认结束后才返还；有效缓存 FD 继续占用自己的额度。关闭最多等待 15 秒，未完成返回 `shutdown_pending` 并停止新接单。无法确认 close 结果时不重试整数 FD，保留占用，等待旧进程真正退出；不盲目启动接管实例。

## 发布与回滚

候选与回滚只从明确的便携文件清单构建并核对完整指纹，不包含测试原件、本机配置或认证值。兼容回滚包关闭新出口和新文件写入，保留私有保护与已有保存任务／发布事实的只读检查；不会迁移或重置已有状态。切换计划必须明确这项回滚影响。

重启会使旧实例／窗口／导出 ID、历史游标与候选预览失效。正常恢复需要新实例下的显式新请求及所需哈希约束。生产切换、连接权限变化和 Git 归档均需独立授权；本开发目录不作为已上线证明。
