# 候选文档交付

候选交付用于把讨论后的研究报告、计划或评审意见保存到本地项目，再由用户决定是否让 Codex 继续处理。保存不代表正式决策或验收，也不会自动启动 Codex。

在 v2，加入项目白名单即可使用候选文档工具。候选固定保存到配置的默认项目目录下。候选工具使用项目的默认目录，原件保存工具支持显式选择 worktree。

## 候选保存位置

v2 默认使用 `docs/candidates/chatgpt`。预览会固定目标路径、最近已有的父目录、调用者和项目授权代次。路径缺失时，按确认后的预览创建必要目录。可配置 `candidate_directory` 以指定另一处候选目录。

v1 沿用项目原有设置。先在项目内创建专用目录，再为项目填写 `candidate_directory`，例如以下配置。

```json
"candidate_directory": "docs/candidates/chatgpt"
```

候选目录必须在项目根目录内，路径中包含 `candidates`，并符合项目路径策略。

仅能在指定目录这一层新建 `.md` 文件，不允许子路径、覆盖、更新、删除或重命名。中文或英文文件名可以使用字母、数字、连字符和下划线；禁止 `AGENTS.md`、`CLAUDE.md`、`SKILL.md`。迭代内容应另存为 `-v2.md` 等新文件。

## 使用流程

1. 在 MCP 客户端查阅资料并讨论内容。
2. 请求“把这份内容准备为 my-project 项目的候选文档，文件名 research-plan-v1.md，先展示预览”。`prepare_candidate` 返回目标项目、具体路径和完整文档。
3. 核对正文与目标后，请求保存。`save_candidate` 参数包含完整正文、项目、路径、SHA-256 和准备凭据；通过客户端原生写操作确认批准这次操作。
4. 保存成功后取得绝对路径和哈希，必要时用 `read_file` 回读。之后可以另行明确要求 Codex 读取、评估或执行其中的部分内容。

在 ChatGPT 使用时，应选择“允许读取”或等效的“读取免询问、更改前询问”设置，避免给候选保存持续的自动写入授权。实际选项以当前客户端为准。

## 确认与内容绑定

`prepare_candidate` 不修改项目，标记为 `readOnlyHint=true`。`save_candidate` 标记为 `readOnlyHint=false`，可审查参数包含实际写入的完整正文和路径。服务添加的候选声明、交付编号与准备时间都包含在预览中，不在确认后暗加内容。

准备凭据签名绑定项目、配置根、仓库身份、相对路径、目标目录身份、正文 SHA-256 和一小时期限。内容、路径、哈希或授权策略不匹配时，旧凭据会被拒绝。

**准备凭据不是用户批准证明。** 标准 MCP 请求没有可信的“用户已点击批准”字段；本实现依赖受信任客户端的原生确认与登录边界。服务端不能证明任意客户端是否真的展示过确认。使用本机 stdio/HTTP 的客户端也需要自行落实用户确认。

如果用户把客户端设置为自动批准，服务端无法强制其展示弹窗。配置远程连接时，应实际验证一次准备、确认、保存流程；不要仅凭工具标记推定 UI 已要求批准。

## 写入、冲突和重试

服务先向同目录的随机临时文件写入完整字节并同步，再用 macOS `renameatx_np(RENAME_EXCL)` 或 Linux `renameat2(RENAME_NOREPLACE)` 原子发布。平台或文件系统不支持时拒绝写入，不退回可能覆盖已有文件的方案。

写入前后检查目录描述符、符号链接、硬链接、文件身份和完整内容。任何同名条目都会导致拒绝；只有同一交付凭据对应的完整文件才返回 `already_saved`，不会产生第二份文件。

响应丢失时，应先原样重试返回的 `save_arguments`。已完成的操作会返回原回执。文件之后被修改或删除时，不会覆盖或自动重建。若发生 I/O 错误并提示结果不确定，应先核对目标文件，不要盲目换文件名重试。

预览一小时后或服务重启后失效。签名密钥仅保存在内存中；重启后旧请求会被拒绝，无论此前是否保存成功。应先读取目标确认，再决定是否准备新交付。单进程最多记住 4096 次写尝试，达到后需重启并重新准备。

突然掉电或强制结束可能留下隐藏临时文件，但不会把半份内容发布为最终目标。服务不会自动清理未知文件或作破坏性回滚。

这些检查约束 MCP 工具的路径、内容、覆盖和重试行为，不隔离已拥有同用户本机写权限的其他进程。并发移动、删除或替换若在核验中被发现，服务会报错；成功回执只证明核验当时的状态，不能阻止此后编辑。

## 限额与维护

完整文件（含候选声明）最大 48 KiB UTF-8；HTTP 请求体上限为 256 KiB，以容纳 JSON 转义和准备凭据。候选工具不会执行命令、Git 操作、部署或回测。

审计记录工具、目标路径、内容哈希、结果和耗时，不记录正文或准备凭据。v2 的项目列表标注可使用项目能力，具体操作仍检查当前目标和服务配置。v1 的 `access: read-only` 字段描述读取接口，候选保存由 `candidate_directory` 配置。

本地测试命令：

```sh
.venv/bin/python -m unittest discover -s tests -v
```

测试通过不代表某个客户端已完成写确认验证。连接或更新服务后，应刷新客户端工具列表，确认 `prepare_candidate` 为读取工具、`save_candidate` 为写入工具，并用专用测试项目验证一次完整流程。

远程连接与认证见 [部署说明](deployment/README.md)。仓库与工作目录读取规则见 [REPOSITORY_ACCESS.md](REPOSITORY_ACCESS.md)。
